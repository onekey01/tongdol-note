# 한글 서식(.hwpx)에 값 채워 넣기 — 지켜야 할 규칙

여덟 번 실패하며 알아낸 것을 정리합니다.
청구서·계약서를 붙일 때 같은 데서 넘어지지 않으려고 남깁니다.

---

## 한 문장으로

> **한글은 "적어둔 숫자와 실제 내용이 어긋나면" 파일을 거부합니다.**

`.hwpx` 안에는 눈에 보이는 글자 말고도, 한글이 화면에 그리려고
미리 계산해둔 숫자가 잔뜩 들어 있습니다. 행이 몇 개인지, 이 칸이 몇 번째
행인지, 이 줄이 세로 어디쯤인지, 몇 번째 글자에서 줄이 접히는지.

글자만 바꾸고 이 숫자를 안 고치면 문서가 자기모순에 빠집니다.
그때 나오는 메시지가 **「손상되었거나 변조되었을 가능성이 있습니다」** 입니다.

---

## 규칙 여덟 개

### 1. 이름표(namespace)를 원본 그대로 둔다
파이썬이 `hs:sec` 을 `ns0:sec` 으로 바꾸고 안 쓰는 선언을 지웁니다.
XML 규격으로는 같은 문서지만 한글은 거부합니다.
→ 원본의 선언 목록을 읽어 그대로 등록하고, 여는 태그도 원본 것을 씁니다.

### 2. zip 포장도 원본 그대로 만든다
`version.xml` 과 그림은 **무압축**으로 들어 있습니다. 순서·날짜·속성도 다릅니다.
→ 항목마다 원본의 포장 정보를 그대로 복사합니다.

### 3. 행을 늘리거나 줄이지 않는다
행 개수(`rowCnt`)와 칸마다 박힌 행 번호(`cellAddr`)를 다시 맞춰도 안 됩니다.
→ 서식이 가진 줄 수 안에서 씁니다. 넘치면 장을 나눕니다.

### 4. `ctrl` 이 든 run 은 건드리지 않는다
`colPr`(단 설정) 같은 부품이 들어 있고 문단 맨 앞에 있어야 합니다.
→ 부품이 든 run 은 그대로 두고 **글자만 든 run** 에만 씁니다.

### 5. `run` 을 지우지 않는다
비어 보이는 `<hp:run charPrIDRef="12"/>` 도 지우면 안 됩니다.
→ run 개수를 유지하고, 남는 것은 글자만 비웁니다.

### 6. 글자모양 번호를 바꾸지 않는다
`charPrIDRef` 를 10에서 13으로 갈아끼웠다가 거부당했습니다.
→ **색이나 모양을 바꿀 일은 한글에서 서식 파일을 고칩니다.** 코드로 바꾸지 않습니다.

### 7. 줄을 늘리면 세로 위치를 다시 계산한다
한글은 줄마다 `vertpos` 를 1500씩(글자 1000 + 줄간격 500) 내려 적습니다.
문단을 복제하면 전부 0이 되어, 24줄이 같은 자리에 겹친 문서가 됩니다.
→ `vertpos = 첫줄 + 한줄높이 × 줄번호`

### 8. 줄 정보(`lineseg`)는 하나만 남긴다  ← **마지막 관문**
칸 너비를 넘어 접히는 글자는 줄 정보가 여러 개 적혀 있습니다.

```
"청소하기, 빨래하기, 식사준비, 기타"
  <lineseg textpos="0"  .../>
  <lineseg textpos="12" .../>   ← 12번째 글자부터 둘째 줄
```

여기에 8자짜리 글을 넣으면 **8자 글에 12번째 글자 위치가 적힌** 문서가 됩니다.
→ 줄 정보를 하나만 남기고 `textpos="0"` 으로 되돌립니다.
   화면 계산 결과일 뿐이라 한글이 열 때 알아서 다시 계산합니다.

## 반드시 돌려야 할 검사

### 검사 1 — 손 안 댄 재저장이 원본과 같은가
```
읽는다 → 아무것도 안 고친다 → 저장한다 → 원본과 1바이트라도 다른가?
```
규칙 1·2를 잡아냅니다. 새 서식을 붙일 때 **가장 먼저** 이것부터 돌립니다.

### 검사 2 — 저장 직전 부품 수 세기
```
colPr · ctrl · 표 · 칸  →  하나도 늘거나 줄면 안 됨
늘어난 run 수 == 늘어난 문단 수
```
규칙 3·4·5를 잡아냅니다. 어긋나면 파일을 만들지 않고 멈춥니다.

## 서식을 새로 붙일 때 순서

1. **한글에서 서식을 먼저 다듬는다** — 예시 글자 지우기, 색·기울임 없애기.
   코드로 우회하지 말고 서식 자체를 고치는 편이 훨씬 안전합니다.
2. 검사 1을 돌린다. 통과 못 하면 그 서식은 아직 못 씁니다.
3. 칸 위치(행·열 번호)를 확인한다.
4. 값을 채우고 검사 2를 통과시킨다.
5. **한글에서 열어본다.** 이건 건너뛸 수 없습니다.

## 확인할 수 없는 것은 재는 자를 만든다

이번에 여덟 번을 왕복한 진짜 이유는, 제가 한글을 띄울 수 없는데
XML을 눈으로 보고 "맞아 보인다"로 판단했기 때문입니다.

효과가 있었던 것은 **한 번에 하나씩만 다른 파일 여러 개를 보내
어디서 처음 막히는지 재는 방식**이었습니다.

- A~E: 행을 건드리는 게 문제임을 밝힘
- H·I·J: 글자모양 번호가 문제임을 밝힘
- K: 한 칸은 되고 한 줄은 안 됨을 밝힘
- M·N: 줄 수가 아니라 특정 칸이 문제임을 밝힘
- P: 줄 정보가 범인임을 확인

그리고 결정적이었던 것은 **작성예시 파일** 이었습니다.
한글이 직접 만든, 우리가 하려는 바로 그 내용이 든 파일.
`vertpos` 가 1500씩 올라가는 것을 거기서 봤습니다.

> 확인할 수 없는 영역에서는, 맞히려 하지 말고 **정답지를 구하거나 재는 자를 만든다.**
